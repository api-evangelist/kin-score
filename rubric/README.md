# Rubric snapshots

Versioned snapshots of the Kin Score rubric. Each `scoring-<version>.yml` is the published record of
that rubric version — the facet weights, the artifact checks and their points, the output bands, the
standalone Agent Readiness block, and (0.5+) the conditional `regulatory` facet and
`industry_regulatory` applicability map.

**Source of truth:** the operational rubric and scorer are maintained in the `api-search` repository
(`signals/_data/scoring.yml` + `signals/score.rb`). These snapshots are published here on each
version bump so the score stays citable and its history auditable. See [`../CHANGELOG.md`](../CHANGELOG.md).

| Version | File | Notes |
|---------|------|-------|
| 0.15.1 | [`scoring-0.15.1.yml`](scoring-0.15.1.yml) | **A tracked signal, not a scored one.** No dimensions, no weights, no change to the 139-point denominator, no band re-cut — scores stamped 0.15.0 stay correct. Adds a third list to the agent-readiness layer: `observed_signals`, for a signal that is fully implemented and running on every pass and finds nobody. `dimensions` are scored; `planned_dimensions` are blocked on a capability we lack; these are blocked on the catalog. First two entries are RFC 10008 (the HTTP QUERY method, Proposed Standard June 2026): `accept_query` — the response header a resource uses to advertise QUERY support and its query media types, the only machine-readable declaration this rubric tracks that is served BY the resource AT request time rather than sitting in a document elsewhere — and `query_method`, the method declared in an OpenAPI 3.2 `additionalOperations` block. **Both observed at zero of 26,641 providers.** Scored at zero points on purpose: a dimension nobody can earn is a rescale, not a measurement — four points with zero earners divides every provider by 143 instead of 139 and moves ~1,900 across a band cut without anyone having gotten worse at anything (the 0.5.1 `agent_card` failure). Each pass prints the count; 25 providers — the headers catalog's own promotion line — graduates a signal to a scored dimension. |
| 0.15.0 | [`scoring-0.15.0.yml`](scoring-0.15.0.yml) | **A frontier dimension that was mostly measuring a security contact file.** `consent_identity` accepted `SecurityTxt` alongside AIPREF, Content-Signals, Web Bot Auth and HTTP Message Signatures — and across all 27,500 catalog repos, 1,089 providers earned the three points with **1,015 of them (93.2%) earning it on security.txt alone**. An RFC 9116 disclosure contact expresses no AI usage preference and identifies no agent. The cost was the finding, not the points: the dimension reported 1,089 providers with an agent-consent posture when 74 have one (ContentSignal 72, HTTPMessageSignatures 1, AIPREF 1, Web Bot Auth **0**). security.txt still scores under `well_known_published`, so nobody loses the signal. Agent-readiness bands re-cut. |
| 0.14.0 | [`scoring-0.14.0.yml`](scoring-0.14.0.yml) | **Three checks that measured the wrong thing.** No new dimensions and no weight changes, so the denominator is unmoved. `llms_txt_published` stops paying for a file WE generated — 2,755 of the 8,976 providers holding one carry a marker saying the enrichment pipeline wrote it, the same defect `CATALOG_HOSTS` already guards for apis.json; marker-based, so that is a FLOOR and 6,221 unmarked files keep the credit. `mcp_server` stops scoring zero for absence from a FROZEN probe snapshot — 119 providers with a non-empty `mcp/` were forfeiting twelve points for being catalogued after 2026-08-18, and now fall back to authorship at the `documented` tier (61 move; never `verified`, because nobody probed them). Retired providers' redirect stubs are no longer scored or left carrying `composite: 0.0, band: minimal`. |
| 0.13.0 | [`scoring-0.13.0.yml`](scoring-0.13.0.yml) | **The OIDC discovery document, finally read.** `auth_clarity` gains a `served` tier at 0.90 — a served `openid-configuration` carrying `issuer`, which the pipeline had been probing on 5,881 providers and saving on 889 while no check read it as OIDC. Tests the required field, not the media type. Adds three dimensions — `delegated_identity` (6), `protected_resource_metadata` (5, RFC 9728) and `dynamic_client_registration` (6, RFC 7591), all read from documents already harvested — plus `agentic_commerce` (5, UCP/ACP with operator attribution — 193 of 197 documents are Shopify's, not the merchant's) — raising max 117 -> 139 and rescaling every agent score by 0.8417. Batched with 0.12.2 so all of it shares one band re-cut. |
| 0.12.2 | [`scoring-0.12.2.yml`](scoring-0.12.2.yml) | **The first 0.12.x that moves points.** `auth_clarity` graded by scheme class — bound 1.00 / negotiable 0.75 / bearer 0.35 — because the IETF agent-auth draft calls a static API key an antipattern for agent identity, and the dimension was paying it the same ten points as OIDC. Plus the well-known soft-200 filter now honours all seven ways the harvest records a miss instead of only the note text: 1,521 credited holdings withdrawn across five frontier targets. |
| 0.9.1 | [`scoring-0.9.1.yml`](scoring-0.9.1.yml) | **Swagger 2.0 is a contract.** A reader fix, not a rubric change — no weight, point value or band moved. The scorer classified a spec by looking for `openapi:` and every check read the 3.x container keys, so a 2.0 document was dropped from the spec index before a single check ran and a provider whose whole corpus is 2.0 scored as publishing no contract at all: 190 of a 3,024-file sample across 90 providers. The index gained ~5,800 documents and 203 providers. |
| 0.9 | [`scoring-0.9.yml`](scoring-0.9.yml) | **`asyncapi_events` renamed `event_surface_described` and widened.** A webhook can be described in OpenAPI: 125 providers use the 3.1 `webhooks` object (87) or `callbacks` (39) against zero publishing AsyncAPI. Adds `provenance.first_party_when` so a multi-class dimension grades against the class that actually satisfied it. 100 false negatives corrected, 19 false positives restored to first-party. |
| 0.8 | [`scoring-0.8.yml`](scoring-0.8.yml) | **The provenance half-measure closed.** Every check in the `openapi` block is provenance-graded, not just `contract_present` — 132 points instead of 20. 318 providers fall, none rise. |
